# Recursos y comunidad

## 📚 Para aprender fundamentos

- **OWASP Top 10** (web) y **OWASP API Security Top 10** — la base de qué tipo de fallos existen y por qué importan.
- **PortSwigger Web Security Academy** — laboratorios gratuitos y guiados, probablemente el mejor recurso gratuito que existe para aprender técnicas web paso a paso.
- **HackTheBox / TryHackMe** — plataformas de práctica con máquinas y retos, muy buenas para soltar la mano en un entorno legal.
- **Programas de recompensas públicos con "Hall of Fame"** — leer reportes ya publicados (disclosed reports) en HackerOne/Intigriti/YesWeHack es una mina de oro para ver cómo se redacta y qué se considera válido.

## 👥 Comunidad

- Foros y Discords/Telegrams de bug bounty (comunidades hispanas y globales).
- Twitter/X: muchísimos hunters comparten técnicas, writeups y CTFs.
- Blogs de writeups (búsquedas tipo "bug bounty writeup IDOR", "bug bounty writeup JWT").
- Conferencias y CTFs: no solo para competir, también para aprender técnicas nuevas.

## 🧠 Cómo estudiar un reporte ajeno ya publicado

Cuando leas un writeup o un reporte disclosed, no te quedes solo con "vale, encontró tal cosa". Fíjate en:

1. Cómo estructuran el resumen inicial (2-3 frases que enganchan al triager).
2. Cómo separan "pasos de reproducción" de "impacto".
3. Qué evidencias exactas aportan en cada paso.
4. Cómo argumentan la severidad/CVSS.
5. Cómo responden si el programa pide más información (si el hilo de comentarios está visible).

## 🗺️ Progresión sugerida (orientativa, no dogma)

1. Fundamentos web (HTTP, cookies, sesiones, CORS, same-origin policy).
2. OWASP Top 10 con laboratorios prácticos (PortSwigger Academy).
3. Primeros programas VDP sin presión económica, para pulir cómo reportas.
4. Especialización progresiva: elige 1-2 áreas que te llamen (APIs, apps móviles, lógica de negocio, cloud...) y profundiza.
5. Programas privados según vayas ganando reputación/puntos en las plataformas.
